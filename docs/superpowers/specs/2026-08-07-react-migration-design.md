# CAS Website — Static → React Migration Design

- **Date:** 2026-08-07
- **Status:** Approved (design). Implementation plan not yet written.
- **Supersedes:** the partial Astro migration in `web/`
- **Source brief:** `docs/master.md`

---

## 1. Context

The Centre for Advanced Studies (AKTU) site is currently produced by a hand-written
Python static site generator.

| Layer | State (measured 2026-08-07) |
|---|---|
| Generator | `build/` — 6,384 LOC across 42 modules |
| Output | `site/` — **392 HTML pages** |
| Design system | `assets/css/` — 101 KB (`tokens.css` 14 KB, `base.css` 8.7 KB, `components.css` 78.6 KB, 34 component sections) |
| Client JS | `assets/js/` — 49 KB vanilla (`app.js`, `facets.js`, `palette.js`, `search.js`) |
| Prior attempt | `web/` — Astro 7 + React 19 islands. 3 route files, 1 island, 11 JSON collections. Builds 160/392 pages in 11.8 s. |
| Content | 13 faculty, 32 former faculty, 9 staff, 5 visiting, 9 programmes, 48 equipment records, 158 documents, 16 publications, 10 patents, 9 projects, 42 events, 6 notices |

The Astro attempt is abandoned by this design (see §9). Its data export pipeline and
`DocumentFilters.tsx` are salvaged; the rest is deleted.

### 1.1 Decisions taken

Three architectural questions were put to the project owner on 2026-08-07:

| Question | Decision |
|---|---|
| SPA vs. Astro islands vs. prerendered React | **React 19 + Vite + React Router, prerendered to static HTML** |
| Redesign during migration, or parity first? | **Parity first, then a premium layer on top** |
| Tailwind or CSS Modules? | **CSS Modules over the ported token layer** |
| Which Phase 8 features are real? | Search/filters/sort/pagination; theme/motion/lazy/error boundaries; CMS-ready data layer |

### 1.2 Non-goals (explicitly dropped)

- **Auth, roles, personalisation.** No backend, no login, no profile store exists or is
  planned. Building a role system with no users produces dead abstractions.
- **React Query / TanStack Query.** `master.md` scopes it to "if APIs exist". None do.
  All content is prerendered from local data; a cache layer over `import` is waste.
- **URL changes.** The 392 public URLs are indexed at `cas.res.in` and must survive
  byte-identical. This constrains the prerender output shape (§3.2).

## 2. Stack

```
React 19.2 · Vite 8 · TypeScript 7 · React Router 8 (framework mode) · Motion 13
```

React Router 8 framework mode is the mechanism for prerendering. `react-router.config.ts`
declares `ssr: false` together with a `prerender` list covering every URL. Route loaders
execute at **build time**; each URL is written as a complete HTML document; the app
hydrates into a full client-side SPA after first paint.

This satisfies both halves of the brief that are normally in tension: React Router really
owns routing (not a shim over a static generator), and crawlers still receive rendered
HTML for all 392 URLs.

**Cost, stated honestly.** Every page ships and hydrates a React runtime that the current
vanilla site does not. Roughly 180 KB of framework JS reaches a visitor reading a static
faculty biography. This is the accepted price of the chosen architecture; §8 lists the
mitigations that keep Lighthouse ≥ 95 achievable anyway.

## 3. Routing

### 3.1 Route modules → prerendered pages

392 pages are generated by roughly 20 route modules. Dynamic segments draw their slug
lists from the data layer, so adding a record adds a page with no routing change.

| Route module | Pages |
|---|---|
| `/` | 1 |
| `/about`, `/admissions`, `/campus`, `/contact`, `/search`, `/sitemap` | 6 |
| `/academics` (+ `btech`, `mtech`, `phd`), `/academics/programs` + `:slug` ×9 | 14 |
| `/people` + `faculty`·`former`·`staff`·`visiting` directories + `:category/:slug` | 64 |
| `/research` + `facilities` + `equipment`·`patents`·`projects`·`publications` + `:type/:slug` | 89 |
| `/updates` + `events`·`notices` + `:type/:slug` | 51 |
| `/documents` + `:slug` ×158 | 159 |
| Trust: `/privacy`, `/terms`, `/copyright`, `/accessibility`, `/security` | 5 |
| Errors: `/404`, `/500`, `/maintenance` | 3 |
| **Total** | **392** |

Breakdown of the two largest groups, for verification:
`people` = 1 index + (13+1) faculty + (32+1) former + (9+1) staff + (5+1) visiting = 64.
`research` = 1 index + 1 facilities + (48+1) equipment + (10+1) patents + (9+1) projects +
(16+1) publications = 89.

### 3.2 URL shape — a build gate, not an assumption

Live URLs are directory-form with a trailing slash: `/about/`,
`/people/faculty/vijay-singh/`. The prerender must therefore emit `about/index.html`,
**not** `about.html`.

The exact output shape of React Router 8's prerenderer has **not been verified** at the
time of writing. Stage S1 must confirm it empirically and, if the default is flat
`.html` files, add a post-build step that reshapes the output into directory indexes.
No further stage may begin until all 392 URLs resolve in their live form.

The same constraint applies to the Astro config that this design replaces, which used
`format: 'file'` plus compensating canonical tags — a workaround this design does not
inherit.

## 4. Data layer

`build/export_json.py` already machine-exports all 11 collections from the Python record
modules. That export runs **once more**, and its output becomes the permanent source:

```
src/data/
  collections/*.json    11 files, exported from build/data/*.py — never retyped
  schema.ts             TypeScript types for every record shape
  loaders.ts            getFaculty(), getDocuments(), … — the single CMS swap point
```

Route modules import from `loaders.ts` and never touch JSON directly. Replacing the JSON
with a headless CMS or API later means rewriting one file, not 392 pages. That is the
whole of the "CMS-ready" requirement; no speculative adapter layer is built.

**Transcription risk is zero by construction.** Institutional content — programme names,
seat counts, patent numbers, faculty credentials — is exported by script, never hand-typed.
This preserves the constraint already documented in `build/export_json.py` and
`build/pages/documents_pages.py`.

Documents are derived at build time from the crawl CSVs in `research/`, so those CSVs are
provenance, not dead weight, and are retained (§9).

The Python modules stay in place as the **verification oracle** until parity passes (§8),
and only then are deleted.

## 5. Styling

```
src/styles/tokens.css      global — ported as-is
src/styles/base.css        global — reset, typography, layout primitives
src/components/Card/Card.tsx + Card.module.css      co-located, scoped
```

`components.css` (78.6 KB, 34 sections) is split into per-component `.module.css` files
co-located with their `.tsx`. Tokens remain global and unmodified.

**The existing dark-mode rule is preserved verbatim:** colour is declared once per token
via `light-dark()`, and no component may write a dark-mode selector. `tokens.css` documents
why — duplicated dark palettes had already drifted once and shipped a white footer on a
dark page. Any component that looks wrong in dark mode is using a raw colour and the
component gets fixed, not the theme.

### 5.1 Pre-hydration scripts that must stay inline

Two scripts in `templates/_layout.html` run before first paint and must remain inline in
the document head, ahead of hydration:

1. **Theme resolution** — reads `localStorage["cas-theme"]`, sets `data-theme`. Deferring
   it causes a flash of the wrong theme.
2. **`--chrome-h` measurement** — measures header height so a full-viewport hero sizes
   correctly on first layout. The original comment records that running this from `app.js`
   instead cost **0.06 CLS**. CSS carries a 140 px fallback, so it is a refinement, not a
   dependency.

`js-on` class handling is also preserved: without JS the class is absent and all content
renders visible, keeping scroll-reveal from hiding content for non-JS visitors.

## 6. Components and features

```
src/
  layouts/RootLayout.tsx    header, footer, skip-link, notice ticker, theme provider
  components/               primitives — Card, Chip, Badge, Breadcrumbs, Pagination, …
  features/                 CommandPalette, DocumentFilters, directories, listings
  routes/                   route modules
  hooks/useCollection.ts    filter + sort + paginate, synced to search params
```

| Feature | Approach |
|---|---|
| ⌘K command palette | React component; native `<dialog>` focus trap retained. A Vite plugin builds the search index at build time; the index (~55 KB) is **lazy-fetched on first open**, keeping it off the critical path — the behaviour the current `palette.js` already achieves. |
| Document filters | Port `web/src/components/DocumentFilters.tsx` (299 lines, already written). Facets: type, area, year, session. State synced to URL. |
| Listings | Shared `useCollection` hook drives faculty, publications, patents, equipment, events. Search-param-driven so filtered views are linkable and prerender-safe. |
| Theme | Context provider over the existing token system; the inline pre-paint script (§5.1) remains authoritative for first render. |
| Motion | Route transitions, scroll reveal, animated counters — all gated behind `prefers-reduced-motion`. |
| Resilience | Route-level error boundaries, `lazy()` code splitting, skeleton loaders. |

Known Chrome behaviour to carry forward: the UA stylesheet caps `dialog` at
`max-width: calc(100% - 38px)`, which previously overrode the palette width. The port must
keep the existing override.

## 7. SEO, head, and accessibility

Per-route `meta` exports supply title, description, canonical, and Open Graph tags,
replacing the `{{TITLE}}`/`{{CANONICAL}}` template substitution. Preserved from
`_layout.html`: self-hosted fonts with no third-party origin, preload of latin subsets
only (latin-ext loads on demand via `unicode-range`), paired `theme-color` for light and
dark, and the skip-link to `#main`.

Accessibility target is WCAG AA. The prior session's audit ran 58 checks; that suite is
re-run against the React build as part of S6. One finding from it is carried forward as a
regression test: visible button text must match its `aria-label` (WCAG 2.5.3, Label in Name).

## 8. Verification

Deletion is gated on evidence, per the brief's "verify every deletion before removing it".

A **parity harness** compares each prerendered React page against its `site/` counterpart:

- text content and heading structure
- internal link graph (no route may 404)
- `<title>`, description, canonical, OG tags
- all 392 URLs resolve in directory form (§3.2)

Nothing is deleted until the harness passes on all 392 pages. After deletion: Lighthouse
≥ 95 on a representative sample (home, a listing, a detail page, the document index),
Core Web Vitals, WCAG AA audit, and bundle analysis.

## 10. Implementation stages

| Stage | Deliverable | Gate |
|---|---|---|
| S1 | Vite + RR8 scaffold; prerender emits directory-form URLs | §3.2 verified empirically |
| S2 | Design system ported: tokens, base, inline pre-paint scripts | Dark mode + CLS unchanged |
| S3 | Data layer: JSON export, `schema.ts`, `loaders.ts` | Record counts match Python exactly |
| S4 | Route modules — all 392 pages prerendering | Page count = 392 |
| S5 | Interactive features (§6) | Palette, filters, listings functional |
| S6 | Parity harness green; a11y suite re-run | All 392 pages pass |
| S7 | Legacy deletion (§9) | Build still green after removal |
| S8 | Phase 6/7 premium layer — glass surfaces, bento home, motion | Diffed against parity baseline |
| S9 | Optimisation: Lighthouse ≥ 95, CWV, bundle analysis | Targets met |

Stage S8 is deliberately after deletion: the premium redesign lands as a reviewable diff
against a working, verified site, so a visual bug and a migration bug are never confused.

## 11. Risks

| Risk | Mitigation |
|---|---|
| RR8 prerender emits flat `.html`, breaking 392 indexed URLs | S1 gate; post-build reshape step if needed. Blocks all later stages. |
| Hydration cost pushes Lighthouse below 95 | Route-level splitting, lazy search index, motion behind `prefers-reduced-motion`, S9 bundle analysis. Measured, not assumed. |
| Visual regression across 392 pages during CSS split | Parity-first sequencing; tokens ported unmodified; premium layer deferred to S8. |
| Losing institutional content accuracy | Data machine-exported, never retyped; Python retained as oracle until S6 passes. |
| CLS regression from moving `--chrome-h` measurement | Script stays inline pre-hydration (§5.1); 0.06 CLS regression is documented precedent. |
